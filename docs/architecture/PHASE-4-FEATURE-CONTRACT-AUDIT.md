# Phase 4 Feature-Contract Audit

## Status

This is the current scoped feature-contract audit for the maintained `EnhancedSelect` runtime and React, Vue, Svelte, Solid, React Native, and Vanilla adapters. It distinguishes implementation from automated coverage and browser evidence; it is not a claim that every feature is complete or bug-free.

The audit found and corrected two selection-event integration defects: the core element advertised and adapter wrappers listened for `select`, but the core did not emit that event; and the Svelte wrapper could miss event wiring during initialization. The new focused regressions pass in the local contract tests. The full browser and hosted CI matrix for these changes remains pending.

## Corrections made in this audit

1. Added the missing core `select` event. Its detail is produced from the selected item record after selection state updates and emitted before aggregate `change`; `getCapabilities()` already listed it. This restores the event path used by adapter listeners.
2. Changed Svelte native event setup to an element action and gated initial reactive synchronization on listener readiness. The previous asynchronous mount setup could return before the bound host was available, leaving callback events unwired. The Svelte selection callback regression now passes.
3. Added `setError(message: string)` and `clearError(): void` to current API/method documentation; verified the methods on core, React/Vue/Svelte/Solid handles, React Native Web, and Vanilla helpers. The native React Native WebView handle does not expose them and is documented as a platform-specific gap.
4. Corrected virtualization descriptions in current component/API/adapter entry docs: public `virtualized` means chunk rendering, not only visible rows. Guarded viewport-windowing remains private and not production-activated.
5. Reclassified Angular as unsupported, `NativeSelectElement` as legacy, and prior WCAG/AAA/VPAT documents as historical unverified drafts. Accessibility status is not represented as WCAG conformance.

## Remaining gaps and release limits

- Current adapter contracts are not exhaustive. React has 43 pending shared-contract cases; Vue, Svelte, and Vanilla have only narrow focused contracts; Solid lacks a comparable contract file.
- React Native has distinct native WebView and React Native Web implementations, no shared adapter contract suite, and an imperative-handle gap between platforms; platform parity is unverified.
- The shared framework Playwright suite uses the Vanilla playground for scenarios, so it does not independently prove wrapper parity.
- New browser assertions for the `select` event and expanded accessibility flows passed on cached Chromium 151, but still require pinned Chromium/Firefox/WebKit hosted execution. The local environment currently has no Playwright binary matching the committed package revision.
- Manual assistive-technology assessment, comprehensive multi-select/identity edge cases, and full styling-override compatibility remain open.
- Public viewport virtualization, a latency budget, and production activation are not authorized by this audit. The 100 ms End-key candidate remains report-only.
