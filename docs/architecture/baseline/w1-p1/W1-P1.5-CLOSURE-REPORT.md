### 3.1 API (observed)

- **API-032:** `updateConfig` with an invalid `dataLoading` candidate emits a `dataLoadingConfigError` whose `detail` is a structured issues array describing the rejected field; no state mutation.
- **API-060:** `startDataLoading()` after connect emits exactly one initial `search`; repeated calls do not multiply the initial request.
- **API-061:** `getDataLoadingState()` returns a detached snapshot — mutating the returned object does not affect internal state.
- **API-062:** `completeDataRequest(completion)` returns a synchronous classification (`invalid` / `unknown-request` / `stale` / `accepted` / `resource-limit`). For `accepted`, projection is asynchronous and deterministic (observed via `projectionPending` → settled `status`); each terminal status projects to `getDataLoadingState().status` with matching `hasMore`/`error`/rendered values and exactly one `dataProjection` `complete`. Rejections leave snapshot/DOM/event counts unchanged.

### 3.2 Events (observed)

- **EVENT-004:** acknowledged `search`'s `detail.request` reflects the typed query and `normalizedQuery`.
- **EVENT-008:** acknowledged `loadMore` carries a fresh page-mode request at `page: 2` with distinct request id.
- **EVENT-021:** `dataRequestCancel` with `reason` (`config-changed`, etc.) and matching `requestId`/`queryGeneration` key set.
- **EVENT-022:** `dataLoadingConfigError` `detail` is an issues array describing the rejected field.
- **EVENT-020 (Partial):** one `dataProjection` `complete` whose `detail` matches request id/generation/attempt; the `failed`-projection variant is **not** deterministically publicly reachable.
- **EVENT-012 (Partial):** the resource-limit diagnostic carries source/name/bounded detail and mirrors `state.resourceLimit`; boundedness proven **per-result, not global** (replayed completion re-emits). The `acknowledgedProjectionFailed` diagnostic is **not** characterized.
- **EVENT-005 (Missing):** `pageLoaded` is declared-only — bounded runtime negative (not emitted at acknowledged page nor legacy load-more completion) plus source inspection (declared, no dispatch site). Completion is signalled via `dataProjection`/`loadMore`. DEVIATION-02 ADR candidate.
- **EVENT-006 (Partial):** async server-failure `error` `{message,cause}` is emitted before `onError`; broader async error sources remain outstanding.

### 3.3 Lifecycle (observed)

- **LIFECYCLE-005 (Partial):** stale async results are guarded on the public surface — superseded `setSelectedValues` fetches (resolved newer-before-older) apply only the newest selection and emit one `change`; a stale success/failure does not overwrite or surface; a disconnect mid-flight drops the detached result (0 events); an acknowledged stale or unknown-request completion is rejected (`stale`/`unknown-request`), produces no projection, and does not advance state.

## 4. Classification discipline

The closure separates the same four states as prior closures and never conflates them:

- **Observed** — established by public-surface black-box tests at baseline `7e3adf7`.
- **Diagnostic** — only privately reachable; public-surface characterization negative/inconclusive.
- **Missing** — declared but consumes nothing observable on the public surface (EVENT-005).
- **Future Design Decision** — a product/contract decision requiring separate authorization (EVENT-005 `pageLoaded`; DEVIATION-02).

**Private-source inspection is not presented as black-box behavioral proof.** Where evidence relies on source locators (the `pageLoaded` dispatch-site absence; the `maxCursorPages` internal-only field), it is labeled as such and does **not** upgrade a contract.

## 5. Gap dispositions (carried forward, not reclassified)

### API-062 — `Partial` (preserved)

The five-status terminal matrix, async projection, cursor-token-size resource-limit, and rejection non-mutation are characterized. The **cursor-depth** resource-limit subpath is **not** publicly triggerable: `maxCursorPages` is an internal coordinator policy field and is rejected by `validateDataLoadingConfig` as an unknown field (verified by an executable negative test), so driving it would require 256+ real pagination commits — not reliably triggerable in jsdom and only reachable via internals. Preserved as **Partial**; the cursor-depth subpath is documented as OUTSTANDING. Not force-covered through coordinator internals (prohibited).

### EVENT-005 — `Missing` (preserved)

`pageLoaded` is declared in the event map but has no dispatch site; two distinct evidence streams (bounded runtime negative + source inspection) confirm non-emission on the exercised paths, without claiming it can never fire. Preserved as **Missing**; **DEVIATION-02** ADR candidate. **Future decision (not authorized now):** retain as declared-only, or remove from the public type under a separate API-contract decision.

### EVENT-006 — `Partial` (preserved)

The async server-failure `error` shape (with `cause`) and its ordering before `onError` are characterized. Broader asynchronous error sources are owned by P1.5 yet remain outstanding. Preserved as **Partial**.

### EVENT-012 — `Partial` (preserved)

The resource-limit diagnostic is pinned (payload, snapshot mirror, per-result replay). The `acknowledgedProjectionFailed` diagnostic path is **not** publicly characterizable in this increment (only reachable via a private failure-injection seam, which P1.5 prohibits using). Preserved as **Partial** (Existing → Partial, per T2-R).

### EVENT-020 — `Partial` (preserved)

`dataProjection` `complete` is pinned; the `failed`-projection variant has **no deterministic public trigger** established in this increment. Preserved as **Partial**.

### LIFECYCLE-005 — `Partial` (preserved)

Supersession, stale-failure, disconnect, and acknowledged stale/unknown completion are characterized and proven discriminating (all 6 tests fail with production guards neutralized). Cursor/page concurrency and load-more staleness interleavings are not exhaustively characterized. Preserved as **Partial** (Missing → Partial).
