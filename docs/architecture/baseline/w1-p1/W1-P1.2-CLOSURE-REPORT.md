## 4. Consolidated contract (summary — full text in ledger §13)

**Interaction vs. programmatic event/callback chronology:**

| Operation | Sequence |
| --- | --- |
| Pointer/Enter select (single/multi) | `select → change → onChange → onSelect` |
| Multi toggle off | `select → change → onChange → onSelect` (`selected=false`, `multi=true`) |
| Single deselect (allowDeselect) | `select → change → onChange → onSelect` (`selected=false`) |
| Chip / option-level remove | `change → onChange → remove` (no `select`; `index`=source registry index) |
| Clear-control (selection present) | `change → onChange → clear → onClear` (DEVIATION-10 under `required`) |
| Programmatic `setSelectedValues()` | `change → onChange` (no `select`) |
| Programmatic `clear()` | `change → onChange` (no `clear`) |
| Rejected (disabled-blocked / maxSelections) | none |
| Single re-select, `allowDeselect:false` | full select sequence but **no state change** |

**Identity / required / validation (summary):** identity unit is the registry key (not value); single-mode replace keeps first registry-eligible value; multi preserves insertion order; detached selections are retained and reattach by key; `required` preserves selection on `clear()`; `validate()` rejects detached selections (DEVIATION-09); disabled `selectable:false` blocks, `selectable:true` allows.

**Programmatic vs interaction (authoritative):** programmatic mutation emits only `change` (+`onChange`); interaction adds the driving event and its callback. This boundary is the invariant later extraction (engine/adapter) must preserve.
