## 3. Consolidated keyboard & accessibility contract (T4-02 / T4-05)

Every statement below is **`Observed`** at baseline `7e3adf7` and is evidenced by the specs in §2. It is a characterization, **not** a normative WAI-ARIA certification.

### 3.1 Open / close

| Behavior | jsdom (Task 1) | Chromium (Task 2) | Evidence |
| --- | --- | --- | --- |
| Keyboard open (ArrowDown/Up/Enter on closed; Space when enabled & non-searchable) | Opens; emits `open:{}` then `onOpen` | Opens; same events | KBD-001; T2-02 |
| Initial active option on open | **No initial `aria-activedescendant`** when nothing selected | **Pre-activates the first selectable option** (single/multi with a selection); empty multi still no active | KBD-001; T2-02; T3-01 |
| Escape | Closes; `close:{}` (no public reason) | Same | KBD-006; T2-03 |
| Tab | Closes the popup | Closes the popup **and focus advances to the next tabbable** | KBD-007; T2-03 |
| Programmatic `open()`/`close()` | Idempotent (double call emits once) | Same | API-030/031 via T1/T2 |
| `open`/`close` detail | `{}` (empty) — **no reason surfaced** | Same | P1.3-D01 |

### 3.2 Navigation (movement, not selection)

- ArrowDown/ArrowUp move the active option by one **selectable** step; disabled options are skipped; movement **clamps** at the first/last selectable option (no wrap). *(KBD-002/009; T2-02)*
- Home/End move to the first/last selectable option. *(KBD-003)*
- PageDown/PageUp move ±10 selectable steps (clamped). *(KBD-004)*
- Type-ahead: an unmodified printable character routes to prefix search; modified keys do not. *(KBD-010)*
- Ctrl/Cmd+A selects all **only** in multi mode and **non-searchable**; otherwise ignored. *(KBD-008; T3-04)*

### 3.3 Range selection (Chromium, Task 3)

- **Shift+Arrow**: the first Shift+ArrowDown from an empty multi selects the landing option (anchor = landing); each subsequent Shift+Arrow extends the contiguous range. Selection is reported in ascending registry order. Plain Arrow does not change selection. *(T3-01)*
- **Shift+Home / Shift+End**: moves the active option to the first/last selectable option and selects **only that endpoint** — it does **not** extend to the full contiguous range. **(P1.3-D05)** *(T3-02)*
- **Ctrl/Cmd+Shift+Arrow**: additive (preserves prior members). **Plain Shift** (without Ctrl/Cmd) **replaces** a pre-existing selection. *(T3-03)*
- **Disabled options**: excluded from the range fill by default; included when `disabledOptionBehavior.selectable=true`. `aria-selected` reflects membership. *(T3-06; T3-08)*
- **maxSelections**: a range clamps at the cap. *(T3-07)*

### 3.4 Selection payloads & chronology

- **Ctrl/Cmd+A** emits **only `change`** (no `select`); payload `selectedValues` in registry order with matching `selectedIndices`. Coverage boundary: the test asserts values, indices, and the absence of a `select` event — it does **not** assert an exhaustive callback-count contract. *(T3-04)*
- **Shift range** per step emits, in order: `select` (detail = moving endpoint, `selected:true`, `multi:true`) → `change` → `onChange` → `onSelect`. A range does **not** emit `open`/`close`. *(T3-09)*

### 3.5 Focus model & ARIA relationships (T4-05)

- DOM focus stays on the host/combobox `<input>`; option elements are **not** focus targets; the active option is expressed via `aria-activedescendant` referencing the option element id. *(KBD-011; T2-04)*
- `aria-expanded` reflects open/closed; `aria-activedescendant` is set on move and cleared on close; `aria-controls` points at the listbox id. *(KBD-012; T2-05; T3-08)*
- **ARIA-busy**: the **listbox** is the reflection target; when genuinely busy it carries `aria-busy="true"` (DOM) **and** the Chromium AX listbox node reports `busy=true`. The legacy host `aria-busy` is intentionally inert. *(ATTR-003; T2-09; P1.3-D02 resolved)*
- **Selected-first** (`selectedOptions.placement='selected-first'`): at the tested configuration the rendered option DOM order and keyboard navigation remain **registry order** (no reorder). This is a bounded observation for the tested configuration, **not** a statement about every visual projection path. **(P1.3-D06)** *(T3-05)*

## 4. jsdom vs certified Chromium (T4-03)

The two characterization bases are explicitly distinguished so no reader conflates them.

| Aspect | jsdom (Task 1) | Certified Chromium 156.0.8078.4 (Task 2/3) |
| --- | --- | --- |
| Input | dispatched `KeyboardEvent` on `[part="input"]` | genuine trusted keyboard/pointer delivered by Playwright |
| Initial active on open | **no initial `aria-activedescendant`** (empty selection) | **first selectable option pre-activated** (all observed open paths: focus-open, closed+focused keyboard reopen, pointer-open) |
| `aria-busy` reflection | legacy host attr inert on listbox (jsdom) | listbox reflects `aria-busy="true"` + AX `busy=true` when genuinely busy |
| Tab focus | (closes) | closes **and** advances focus to next tabbable |
| AX tree | not available | CDP `Accessibility.getFullAXTree` assertions |

**Cause of the jsdom/Chromium difference is withheld (P1.3-D03).** The browser observation is preserved and characterized per open path; the discrepancy is not attributed to a single cause.

## 7. Explicit limitations preserved (T4-07)

- **Cross-browser:** All real-browser evidence is **Chromium (Chrome-for-Testing 156.0.8078.4) only**. Firefox, WebKit, and mobile engines are **not** characterized. No cross-browser parity is claimed.
- **Screen readers:** All accessibility findings rest on the **Chromium AX tree** (roles, names, states, `aria-*` relationships). They establish that the AX *representation* is correct; they do **not** assert NVDA/JAWS/VoiceOver compatibility, which is out of scope for W1-P1.
- **APG conformance:** Behavior is characterized as-is; deviations from example WAI-ARIA patterns (e.g. P1.3-D03, P1.3-D05) are recorded, not normalized.
- **Coverage boundaries carried by the Lead:** Ctrl/Cmd+A is characterized for values/indices/absence-of-`select` but **not** an exhaustive callback-count contract; P1.3-D06 covers the tested configuration only, not every visual projection path.
