### 3.1 Part tokens (observed)

- The host renders an **open shadow root**; structural parts (`button`, `input`, `listbox`) are in the shadow tree, not duplicated into the host light DOM. *(PART-001/002/003; T1-04 ownership in Chromium t2)*
- Popup parts (`option`, `group-header`, `no-results`) render one-per-item/one-per-group when open; `no-results` renders for an empty data set. *(PART-007/008/010)*
- Control parts (`clear-button`/`clear-icon`) and loading parts (`loading`, `loading-content`, `loading-icon`, `loading-message`, `loading-spinner`) render per the observed control/loading wiring. *(PART-005/006/011)*
- **Chip parts:** multi-select selected values render `chip` + `chip-label` + `chip-remove` + `chip-remove-icon`. The `chip-exiting` transient token is **not reachable through the public surface** in the examined build — preserved as **Partial** (see §5, PART-009).

### 3.2 Attributes / state markers (observed)

- `data-custom-arrow="true"` is set on the host when a custom arrow is slotted and removed otherwise; real-slot flattening in Chromium confirms it. *(ATTR-012)*
- The host inline `style.display` is forced to `"block"` on connection; reconnection re-asserts it over a conflicting caller value (proven in jsdom **and** Chromium). This is the Angular-workaround (DEVIATION-05) characterized as-observed, **not endorsed**. *(ATTR-013)*
- During close, the dropdown carries `data-motion="closing"` while the real exit animation keeps the panel displayed; the marker is removed when the exit completes. jsdom resolves animation duration to 0, so this is a **Chromium-only** observation. *(ATTR-021)*
- Multi-select input container reflects `data-multi-scroll-mode` and `data-drag-scroll`; both are cleared for single-select. *(ATTR-022)*
- **Virtual spacer:** a 2,000-item virtualizable list renders **zero** `data-virtual-spacer` at the tested settled-render checkpoints. The spacer is only reachable via private seams; no public activation path exists. Preserved as **Diagnostic** (see §5, ATTR-023).

### 3.3 API / event / lifecycle (observed)

- **API-002:** getter returns the assigned renderer; the renderer's element becomes the group-header part; identity-preserving re-assignment keeps the public function identity *and* the same rendered header node (public stability, **not** a proof of the internal early-return branch); replacement re-renders; `undefined` restores the default label.
- **EVENT-011:** `emptyStateChange` emits exactly `{context:{query,reason}}` (reason `no-options`|`no-results`) or `{context:null}`; emits **once per real transition** and not on duplicate identical context; `getEmptyStateContext()` returns a frozen `{query,reason}` snapshot. Payload shape preserved exactly.
- **LIFECYCLE-002:** after connect, outside pointerdown closes an open popup; `onOpen` fires once on connect.
- **LIFECYCLE-003:** on disconnect, an open popup closes and rendered options are released (`0 [part="option"]`); the detached element remains closed on outside input. *(Observed behavior only — not a proof of internal listener removal; see §5, LIFECYCLE scoping.)*
- **LIFECYCLE-004:** reconnection re-renders each item once (not doubled) and outside input still closes the popup with **exactly one** public `close` event per open across two cycles. *(An observable invariant — not a proof of exactly one internal document listener.)*

## 4. Classification discipline (T4-08 acceptance rule)

The closure separates four states and never conflates them:

- **Observed** — established by public-surface black-box tests at baseline `7e3adf7`.
- **Diagnostic** — only privately reachable; public-surface characterization is negative/inconclusive (ATTR-023).
- **Missing** — declared but consumes nothing observable on the public surface (CONFIG-023).
- **Future Design Decision** — a product/contract decision requiring separate authorization (the CONFIG-023 disposition below; PART-009 chip-exiting intent).

**Private-source inspection is not presented as black-box behavioral proof.** Where evidence relies on source locators (e.g. the `chip-exiting` token location, the virtualizer seam, the `expandable` declaration), it is labeled as such and does **not** upgrade a contract to `Existing`.

## 5. Gap dispositions (T4-05)

### PART-009 — `Partial` (preserved)

Four stable chip tokens (`chip`, `chip-label`, `chip-remove`, `chip-remove-icon`) are characterized through the public surface. The **`chip-exiting`** transient is **not verified through the public surface** — it renders only during an exit transition that black-box tests cannot deterministically observe. This is preserved as an **unobserved transient**, explicitly **not** a confirmed implementation defect. Upgrade to `Existing` is deferred to a future increment that can observe the transient deterministically (or that wires a public observation point).

### ATTR-023 — `Diagnostic` (preserved)

A public 2,000-item virtualizable list produced **no** `data-virtual-spacer` at the tested settled-render checkpoints (jsdom cannot resolve the layout that would trigger spacing; Chromium negative test records deterministic absence). The guarded virtualizer that emits spacers is reachable only via private test seams; **no public config/method establishes the window**. Existing private-seam evidence does **not** establish publicly reachable spacer behavior. Preserved as a **characterization gap**; positive spacer behavior remains outstanding and is not forced with a private stub (out of scope).

### CONFIG-023 — `Missing` (preserved)

The `expandable` configuration (`enabled`, `collapsedHeight`, `expandedHeight`, `expandLabel`, `collapseLabel`) is **declared and defaulted in the global config but not consumed by the component** in the examined baseline (`grep` yields only the declaration/defaults, zero component usages). Enabling and toggling it produce no expansion UI, no expand part token, and byte-identical rendered DOM. Preserved as **Missing** with a negative characterization. **Future Product Decision (required, not authorized now):**

- **Implement** the declared capability in a **separately authorized production increment**; **or**
- **Deprecate/remove** the unsupported configuration through a **separately authorized API-contract decision**.

Neither option is approved for implementation during W1-P1. No production change, removal, or ADR is authorized.

## 7. Explicit limitations preserved

- **No browser parity claim.** Real-browser evidence is **Chromium (Chrome-for-Testing 156.0.8078.4) only**. Firefox, WebKit, and mobile are not characterized.
- **No comprehensive lifecycle resource cleanup claim.** LIFECYCLE-002/003/004 characterize *observable* behavior (listener effect, popup closure, rendered-node release, detached state, public `close` count per open). They do **not** prove internal listener cardinality, resource counts, or leak-free cleanup.
- **No implementation-completeness claim.** Characterization establishes that the public surface behaves as observed for the tested scenarios; it does not assert that all source wiring is exposed, nor that nothing else is missing.
- **Intentional transient/negative gaps preserved:** PART-009 (`chip-exiting` unobserved), ATTR-023 (spacer not publicly reachable), CONFIG-023 (unwired config).
- **APG/ARIA conformance** is inherited from W1-P1.3 and not re-litigated here.
