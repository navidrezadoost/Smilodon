## 1. Objective

Characterize, through the **public package surface only**, the security and CSP utility exports and their server-side (no-DOM) behavior — the surfaces the ledger deferred to P1.6 as **documented-only, not certified**.

There are **two independent, currently-uncertified public surfaces** in scope:

1. **Security / HTML-safety utilities** — `packages/core/src/utils/security.ts` (295 lines):
   - Sanitizer registry and boundary: `setHTMLSanitizer`, `resetHTMLSanitizer`, `getHTMLSanitizer`, `sanitizeHTML`, `validateTemplate`.
   - Safe DOM construction: `createElement`, `createTextNode`, `setTextContent`, `setCSSProperties`.
   - Escaping / detection: `escapeHTML`, `escapeAttribute`, `containsSuspiciousPatterns`.
   - Environment capability detection: `CSPFeatures` (`hasInlineScripts`, `hasEval`, `hasSharedArrayBuffer`, `hasWorkers`, `isSandboxed`, `getCSPDirectives`) and `detectEnvironment`.

2. **CSP-compliant styling utilities** — `packages/core/src/utils/csp-styles.ts` (238 lines):
   - `applyClasses`, `toggleClass`, `setCustomProperties`, `getCustomProperty`, `removeCustomProperty`.
   - `defaultTheme`, `applyDefaultTheme`, `shadowDOMStyles`, `injectShadowStyles`.
   - `hasOverflowHiddenAncestor`, `warnCSPViolation`.

3. **SSR / import-time safety** — that these public exports can be **imported in a Node (no-DOM) environment without throwing at import time**, and that DOM-dependent functions **defer** browser access to call time (not import time). This is the "import-time browser deps" gap named in §10.

### 1.1 Current coverage of this surface

- **Traceability matrix:** `W1-P1-TRACEABILITY.json` contains **zero** records for any security/CSP/SSR surface. All 112 existing contracts are `EnhancedSelect` class/DOM contracts (`API, EVENT, ATTR, PART, SLOT, LIFECYCLE, CONFIG, KBD`). Verified: no ID references `setHTMLSanitizer`/`sanitizeHTML`/`CSPFeatures`/`detectEnvironment`/`escapeHTML`/`escapeAttribute`/`injectShadowStyles`/`hasOverflowHiddenAncestor`/`warnCSPViolation`.
- **Existing test:** exactly one suite touches this surface — `packages/core/tests/csp.spec.ts` (363 lines, 30 `it()` blocks). It exercises many helpers, but:
  - It is **not represented** in the traceability matrix (no contract IDs → not certified under the W1-P1 regime).
  - Several assertions are **environment-branch tolerant** rather than contract-pinning — e.g. `expect(typeof hasEval).toBe('boolean')` and `expect(typeof hasInlineScripts).toBe('boolean')` assert only that a boolean is returned, not the contract. These are **diagnostic**, not characterization.
  - The "No eval/Function" describe block (lines ~301-327) is a **meta/non-assertion** (it checks that `window.eval` exists rather than that the library never invokes it) — it does not pin a library contract.
  - There is **no** no-DOM/SSR import test anywhere in `packages/core/tests` or `tests/`.
- **Production consumers:** grep confirms `utils/security.ts` and `utils/csp-styles.ts` are imported **only** by `packages/core/src/index.ts` (re-export). **No component, config, or engine module consumes them.** They are a standalone public utility surface with no internal wiring. This is important: their contracts are **pure function contracts of the package export**, and the driving surface is the public import, not a rendered element.

**Classification thesis.** Because there are no existing contract IDs, this increment must **define** the P1.6 contract set. The current coverage of every P1.6 contract begins at **`Diagnostic`** (a test exercises the helper but does not pin the observable contract under the W1-P1 regime) or **`Missing`** (no governing test — notably import-time/SSR safety). §2 fixes the set and starting class.

## 2. Scope — exact contract set (proposed; defines P1.6)

> **Scope-defining decision.** No contract currently carries `targetIncrement: P1.6`. This plan **defines** the P1.6 contract set. Per the counting convention ("one record per public surface unit"), each helper or tightly-coupled helper group is one contract ID. Grouped surfaces (getter/setter/reset sanitizer family; custom-property set/get/remove family) are single records whose tokens are enumerated in `behavior`.

Proposed IDs reuse **existing verifier-recognized prefixes** (`API`, `CONFIG`) rather than inventing new ones, so the certified matrix/tooling is not forced to change (see §2.4, §11 Q1). Family mapping:
- **`SEC-*` logical family, encoded under `API-0xx`** (public utility function contracts — they are package API).
- **`CONFIG-0xx`** for the environment-capability/config-shaped surface (`detectEnvironment`, `CSPFeatures`, `defaultTheme`).

Final ID allocation is fixed at T1 write-out so as not to collide with `API-001..062` / `CONFIG-001..026`. Illustrative allocation shown below; exact IDs finalized in T1 and recorded in T1 evidence.

## 6. Acceptance criteria

A contract is eligible for a coverage upgrade to `Existing` only when **all** hold:
- **AC-1:** Covered via **public import surface only** (named exports from the package entry or module path; no `as any`/private seam). A harness-integrity guard asserts the P1.6 spec imports only public symbols.
- **AC-2:** Assertion observes the helper's **externally observable** effect: the returned value/string/element, the mutated DOM (`className`, `style.getPropertyValue('--…')`, appended `<style>`), the boolean capability, or the `console.warn`/`console.error` invocation — not an internal implementation detail.
- **AC-3:** **Negative path** included where the contract implies one: `createElement` blocks `on*`/`style`; `setCustomProperties`/`setCSSProperties` reject non-`--` keys and **do not** set them; `validateTemplate` warns **only** under default no-op; `getCSPDirectives` returns `[]` when no meta tags; no-op sanitizer is identity.
- **AC-4:** Test is **deterministic**; console capture uses `vi.spyOn` and is restored; no arbitrary sleeps. SSR test is environment-controlled (no-DOM), not timing-based.
- **AC-5:** Traceability `testId` points to the exact `it()` title (`path#exact title`).
- **AC-6 (SSR only):** The import-time test genuinely runs **without** `document`/`window` (Node environment) and proves the import succeeds and top-level does not touch the DOM; the deferred-access test proves a call-time failure, not an import-time one.

**Increment-level acceptance (regardless of Q1 path):**
- All proposed contracts at AC-1..AC-6, OR explicitly reclassified with Lead-approved justification (§7).
- Full core suite green (≥ 1012 + new); SSR spec green under Node.
- `verify_traceability.py` PASS. **If Path A:** matrix/ledger reconcile with N new IDs and distribution recalculated and stated; **If Path B:** matrix unchanged (112) and PASS retained — recorded explicitly in closure.
- Production isolation: `git diff <starting> -- packages/core/src packages/core/engine packages/core/adapters` is **empty**.
- `csp.spec.ts` and all accepted prior tests unchanged; SHA256SUMS verify.

## 7. Pre-identified risks & classification risks

1. **Scope is a scope-definition (not just characterization).** No P1.6 contracts pre-exist; the plan defines them. Risk: over/under-claiming. Mitigation: one record per public surface unit; grouped families enumerated; ID allocation finalized in T1 and stated in evidence; Lead ratifies count via Q1/Q2.
2. **Dev-only branching (`process.env.NODE_ENV`).** `setCustomProperties`, `warnCSPViolation` behavior depends on `NODE_ENV`. Risk: asserting one branch and claiming the contract. Mitigation: characterize the observable warning contract under the **test** environment (non-production) and record the production-branch as a documented, source-inspected condition (like a deviation), not silently.
3. **Environment-capability booleans are host-dependent.** `hasEval`/`hasInlineScripts`/`hasWorkers`/`hasSharedArrayBuffer`/`isSandboxed` depend on the runtime. Risk: a `typeof === 'boolean'` assertion (as in `csp.spec.ts`) is diagnostic, not characterization. Mitigation: **pin the contract as "returns a boolean and does not throw"** plus a deterministic sub-contract that is stable in jsdom/Node (e.g. `getCSPDirectives` reads injected meta tags; `detectEnvironment` shape and key-presence). Do **not** claim host-specific truth values; record the host-dependence as the contract boundary.
4. **SSR no-DOM proof harness.** jsdom is globally configured in `packages/core/vitest.config.ts`. Risk: the SSR spec silently runs under jsdom and fails to exercise no-DOM. Mitigation: use a per-file environment override (`// @vitest-environment node`) or an isolated Node smoke; assert `typeof document === 'undefined'` at test start as a guard.
5. **`getCustomProperty`/`hasOverflowHiddenAncestor` rely on `getComputedStyle`.** jsdom's computed-style support is partial. Risk: false failures. Mitigation: scope assertions to what jsdom computes reliably (`style.setProperty` round-trips) and mark `getComputedStyle`-dependent expectations as environment-limited; if jsdom cannot observe it, record as Partial/diagnostic, not force.
6. **`console.warn` capture.** Multiple helpers warn. Risk: interleaved/global warn state leaks between tests. Mitigation: `vi.spyOn(console,'warn').mockImplementation(...)` per test with restore; assert call **counts/messages** precisely.
7. **Matrix-extension tooling (Path A).** Adding IDs requires ledger section + JSON edits reconciled 1:1. Mitigation: reuse verifier-accepted prefixes (`API`/`CONFIG`); regenerate `SHA256SUMS`; run verifier; validate JSON with `python3 -c "import json; json.load(...)"`.
