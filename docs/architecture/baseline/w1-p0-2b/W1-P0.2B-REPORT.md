## Attribution and cause

Before the production change, browser instrumentation identified two distinct component-owned scroll listeners when guarded virtualization was active. The tooltip measurement callback was registered on `.input-content` during construction by `_attachEventListeners()` and survived disconnection. The guarded virtualizer callback was separately registered on `.options-container` and removed by `_destroyGuardedVirtualizer()`. The tooltip callback also has a separate `window` registration under the connection `AbortSignal`; aborting that signal removed the window listener. Temporary selected-option scrolling uses a separate local callback and was disabled in this isolated ownership comparison.

The baseline snapshot is in [baseline-attribution-observation.json](browser-evidence/baseline-attribution-observation.json). After the change, [listener-ownership-diagnostic.json](browser-evidence/listener-ownership-diagnostic.json) records callback IDs, targets, stacks, capture/passive options, signal state, and counts through construction, connection, guarded virtualization, disconnection, reconnection, and cleanup. The post-change test used cached Chrome 133 for diagnosis only; it is not certification.

## Change

The same passive `scroll` callback is now attached to `.input-content` in `connectedCallback()` and explicitly removed in `disconnectedCallback()`. Callback identity, event type, and passive option are preserved. Guarded virtualizer listener code is unchanged. Lifecycle stress assertions count input and options listeners independently and check both reconnect restoration and cleanup.
